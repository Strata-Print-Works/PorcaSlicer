# Where to change Porca

Start here when locating a feature. Paths identify the current implementation;
the linked designs explain its contracts. Keep this map current when moving an
owner or changing a verification group. Global product and validation rules live
in [AGENTS.md](../AGENTS.md).

## Feature entry points

Verification names below are groups accepted by
`python3 scripts/verify_offline.py <group>`; use `--list` for exact targets, tags
and test sources.

For pure panel allocation, filament totals, slice queue or discovery policy,
build `porca_unit_tests` and run the `quick` group during iteration. It reuses
existing tests without linking the application libraries. The full groups below
remain the integration checks; `quick` does not replace them.

## Supporting work

- GUI entry and lifetime: [GUI_App.cpp](../src/slic3r/GUI/GUI_App.cpp),
  [MainFrame.cpp](../src/slic3r/GUI/MainFrame.cpp), then the owning feature above.
  Read [GUI instructions](../src/slic3r/GUI/AGENTS.md) before editing native UI.
- Printer/vendor profiles: `resources/profiles/<Vendor>/` and its sibling vendor
  index. Follow the [profile skill](../.claude/skills/orca-profiles/SKILL.md),
  including bundle versions and inheritance checks.
- Translations and extraction: [localization instructions](../localization/AGENTS.md).
  Source files with extracted strings are listed in `localization/i18n/list.txt`.
- Test placement and helpers: [tests/AGENTS.md](../tests/AGENTS.md).
  The runner selects reviewed coverage; it is not a replacement for feature-specific
  tests or native visual review.
- Build/cache diagnosis and offline tooling: [development-builds.md](development-builds.md).
  Generated outputs, review artifacts and local UI studies are described in the
  root instructions; retain inherited source layout and provenance.
