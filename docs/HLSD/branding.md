# Porca branding

Porca's native interface uses the user-supplied brand board retained at `resources/branding/brand-board.svg`. The board's labeled palette is coral `#FF7B7B`, charcoal `#1E1E1E`, and cream `#FAF7F2`. These labels take precedence over the slightly different fills in the traced SVG. The asset manifest records its SHA-256 and the source paths used for the pig mark, wordmark and application icon. Derived SVGs preserve their original geometry and outlined lettering. PNG, ICO and ICNS icons are rasterizations of that vector icon.

The user-supplied design-system handoff is retained in `resources/design-system/`: `BRAND.md`, source and resolved tokens, font sources, and Lucide icon paths. It supplies the warm palette, typography and compact control proportions; repository workflow and compatibility requirements govern their adoption. `scripts/generate_design_tokens.py` generates `GUI/DesignTokens.hpp` from `tokens.json`, resolving color aliases into light/dark semantic roles and exposing spacing, radius, size and type constants. Type roles retain family, weight, logical pixel size and line height. These constants do not automatically restyle existing controls or enforce line height.

`GUI/Branding.hpp` retains the legacy UI palette mapping. The inherited `StateColor` semantic keys resolve to warm light surfaces or charcoal dark surfaces. Coral with charcoal text marks primary actions. A darker coral ink is used for small text and thin icons against cream. Navigation retains a dark surface in both themes, with a muted coral selection surface and coral text. Printer status colors, filament colors and model materials retain their meanings. Generated tokens coexist with this mapping; the native screens are not fully migrated to the handoff.

Custom widgets keep semantic colors in `StateColor`, so their text and backgrounds resolve together when the theme changes. The accent-foreground key resolves to cream on the light theme's darker ink and charcoal on the dark theme's coral. Native windows instead store resolved colors. Their theme pass uses `Branding::window_color` with a background/foreground role to recover mapped light surfaces, preserve explicit brand fills and avoid confusing cream backgrounds with cream header lettering. Repeated theme passes preserve the selected palette.

`GUI/Typography.hpp` and `.cpp` provide native font construction. The shared `Label` font path adopts Figtree for non-CJK system locales while preserving existing measured point sizes, including inherited platform size adjustments; normal and strong weights use the body roles. The explicit `DesignSystem::font(TypeStyle)` factory instead converts the handoff's CSS logical pixels to native points at 72/96. Display roles use Nunito, interface roles Figtree and monospaced roles JetBrains Mono. Exposing a role does not mean every native control uses it. Existing Chinese, Japanese and Korean font choices remain, and an unavailable requested family falls back to the system GUI font.

The bundled static TTF instances are derived offline from the supplied variable WOFF2 files with `scripts/convert_design_fonts.py`, using fontTools and a local Node Brotli decoder. The original fonts and SIL Open Font License notices remain alongside the instances; the manifest records weights, character coverage and asset hashes. These are Latin subsets, not replacements for the existing CJK fonts. Registration runs before shared label fonts are cached: macOS uses process-scoped CoreText registration, other platforms use wxWidgets private fonts, and Linux avoids registering families already installed. The wxWidgets enumeration cache is invalidated after registration.

The Prepare object toolbar uses one compact floating surface across the main actions, separator, gizmos and assembly-view toggle. `GLCanvas3D`, `GLToolbar` and `GLGizmosManager` share a 12-logical-pixel top inset and compact spacing. A light/dark nine-slice texture supplies rounded corners and the handoff's popover elevation, with a transparent gutter for the shadow. The shadow extends beyond the solid surface without enlarging its hit bounds. Drawing, mouse hit testing and tool input-window placement use the same inset. The 28-pixel base control size retains the user's toolbar size preference, DPI scaling and inherited auto-fit behavior. Design and Assemble canvases retain their inherited toolbar layout.

`GUI/ToolbarStyle` supplies theme and interaction colors for the Prepare glyph atlas: muted ink at rest, a hover surface, accent ink on a soft accent selection, and disabled ink. Atlas generation centers 20-unit glyphs inside 28-unit controls with a pixel gutter, scaling both with the toolbar. Basic actions use the supplied Lucide 0.460.0 paths on a 24-unit grid with a 1.75-unit stroke; the Lucide copyright and permission notice is retained. Specialized slicer tools, including support and seam painting, retain Orca glyphs and provenance. Commands, shortcuts, visibility and enablement rules remain those of the existing toolbar.

The exact brand lettering remains in the vector logo assets; raster logo crops from the handoff do not replace it. The splash, About icon, troubleshooting logo, window/dock icons and operating-system display names use Porca assets. The underlying executable, settings key, profile and project formats, URL handlers and package identifiers retain their inherited names; branding does not migrate stored printer connections or settings. Orca service identities, licenses and copyright notices are retained.

Source and asset inspection cannot establish native font metrics, fallback rendering, toolbar appearance or interaction behavior on macOS, Windows or Linux. Those require platform runtime validation, which remains outstanding under the current local validation restriction.
