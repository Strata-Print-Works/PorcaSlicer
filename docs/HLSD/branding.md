# Porca branding

Porca release notes are bundled in `resources/porca-release-notes.txt` and opened from Help. These notes describe changes that have actually landed in Porca; an upstream change belongs in them only after it is integrated and checked in this fork. The application update check has no upstream default: it runs only when `version_check_url` names a Porca release feed. Saved overrides pointing to the inherited Orca version service are ignored, since those releases and their notes do not describe Porca. Printer-profile updates use a separate endpoint and retain their compatibility behavior.

Porca's native interface uses the user-supplied brand board retained at `resources/branding/brand-board.svg`. The board's labeled palette is coral `#FF7B7B`, charcoal `#1E1E1E`, and cream `#FAF7F2`. These labels take precedence over the slightly different fills in the traced SVG. The asset manifest records its SHA-256 and the source paths used for the pig mark, wordmark and application icon. Derived SVGs preserve their original geometry and outlined lettering. PNG, ICO and ICNS icons are rasterizations of that vector icon.

The user-supplied design-system handoff is retained in `resources/design-system/`: `BRAND.md`, source and resolved tokens, font sources, and Lucide icon paths. It supplies the warm palette, typography and compact control proportions; repository workflow and compatibility requirements govern their adoption. `scripts/generate_design_tokens.py` generates `GUI/DesignTokens.hpp` from `tokens.json`, resolving color aliases into light/dark semantic roles and exposing spacing, radius, size and type constants. Type roles retain family, weight, logical pixel size and line height. These constants do not automatically restyle existing controls or enforce line height.

`GUI/Branding.hpp` retains the legacy UI palette mapping. The inherited `StateColor` semantic keys resolve to warm light surfaces or charcoal dark surfaces. Coral with charcoal text marks primary actions. A darker coral ink is used for small text and thin icons against cream. Navigation retains a dark surface in both themes, with a muted coral selection surface and coral text. Printer status colors, filament colors and model materials retain their meanings. Generated tokens coexist with this mapping; the native screens are not fully migrated to the handoff.

Custom widgets keep semantic colors in `StateColor`, so their text and backgrounds resolve together when the theme changes. The accent-foreground key resolves to cream on the light theme's darker ink and charcoal on the dark theme's coral. Native windows instead store resolved colors. Their theme pass uses `Branding::window_color` with a background/foreground role to recover mapped light surfaces, preserve explicit brand fills and avoid confusing cream backgrounds with cream header lettering. Repeated theme passes preserve the selected palette.

`GUI/Typography.hpp` and `.cpp` provide native font construction. The shared `Label` font path adopts Figtree for non-CJK system locales while preserving existing measured point sizes, including inherited platform size adjustments; normal and strong weights use the body roles. The explicit `DesignSystem::font(TypeStyle)` factory uses `font_points` to convert the handoff's logical pixel sizes to native points: one logical pixel per point on macOS, where Cocoa uses 72 logical pixels per inch, and a 72/96 conversion on other platforms. Display roles use Nunito, interface roles Figtree and monospaced roles JetBrains Mono. Exposing a role does not mean every native control uses it. Existing Chinese, Japanese and Korean font choices remain, and an unavailable requested family falls back to the system GUI font.

The bundled static TTF instances are derived offline from the supplied variable WOFF2 files with `scripts/convert_design_fonts.py`, using fontTools and a local Node Brotli decoder. The original fonts and SIL Open Font License notices remain alongside the instances; the manifest records weights, character coverage and asset hashes. These are Latin subsets, not replacements for the existing CJK fonts. Registration runs before shared label fonts are cached: macOS uses process-scoped CoreText registration, other platforms use wxWidgets private fonts, and Linux avoids registering families already installed. The wxWidgets enumeration cache is invalidated after registration.

The Prepare sidebar adapts the handoff's light and dark sidebar direction to the existing native workflow. Printer and material sections use quiet surfaces, muted supporting text and thin dividers. Section headers have a 40-DIP minimum height. The printer identity occupies a full-width card with a 68-DIP minimum height, a bundled model picture (with a printer glyph fallback) and a shared hover/focus frame. Its primary line uses a 16-logical-pixel heading font; the muted secondary line uses a 12-logical-pixel font and summarizes distinct configured nozzle diameters and a recognized material shared by all nozzles. System presets with a configured model name show that name, with the existing modified marker; other presets retain their full label. The dropdown uses the same model pictures in fixed 40-DIP slots; photos keep their aspect ratio and are rasterized for the current display scale. This display does not rename presets or change their selection data, and the tooltip retains the full selected preset name. `mockups/porca-printer-section-study.html` is the layout reference; the native source defines the implemented behavior. Each filament has a shared 34-DIP frame containing three independent controls: its numbered color swatch, preset selector and pencil, with a quiet divider before the pencil. The pencil opens settings consistently. The section overflow selects a filament before opening its inherited action menu; right-click or the context-menu key on any of the three controls opens that menu directly. Merge, color decomposition and deletion retain their native eligibility checks. Two columns and the configured visible-row limit keep larger palettes compact. Shared hover and focus states include all three controls, and the container supports keyboard traversal. Framed selectors retain their borderless presentation through theme and DPI updates. Dark control outlines use the approved Quiet shade, `#403D39`; light outlines retain `#8C857D`. The layout retains its inherited native allocation, including the accepted 403-DIP width; the 360-DIP sidebar token remains a minimum.

Build plate and Nozzle setup sit beneath the identity card as quiet rows with a 38-DIP minimum height and outlined, right-aligned selectors. Their fields and the Tool flow disclosure use the control-line role and a shared 230-DIP minimum width. The build-plate value remains on one line and intact; its row appears only for Bambu presets or printers supporting multiple bed types. Nozzle setup retains the existing printer-variant switch, separate from the identity caption, and is hidden for the native dual-extruder layout. A disclosure row appears when the single group has flow variants or a non-Bambu printer has multiple tools. Its readout reflects the visible selected flow values: a shared value, All standard, All high flow or Mixed flow. When no flow value is available, it offers Show tools under Nozzles. Expanding it reveals an aligned, full-width vertical nozzle listing, with tool labels for multiple tools, measured diameter columns and the existing per-tool flow selectors. The dual-extruder and AMS groups retain their paired layout and editable diameter controls. Add, Connection, synchronization and printer-wizard actions retain their existing handlers and visibility rules, as do material presets, color editing and supported material synchronization.

The printer selector opts into a searchable chooser through `ComboBox` and `DropDown`; other selectors retain their existing popup behavior. Filtering matches the underlying item text, full popup label, alias, group and subtitle without replacing original item indices or client data. Full labels remain available even when the painted row is ellipsized. Section headings remain nonselectable, disabled items cannot be selected or invoke row actions, and row actions use the existing dropdown-action event. The system-printer management item is excluded from the list because Select/remove printers is available in the footer; Create printer remains a list action. Edit printer preset invokes the existing hidden edit button through a weak callback, preserving its editing-state handling. Footer actions dismiss before deferred dispatch, and deferred selection rechecks both owner lifetime and item identity. A failed search shows No printers match your search and Clear search; an empty unfiltered list shows No printers available. The native search editor handles typing. Up/Down opens the chooser from the selector and steps through selectable rows when search or list has focus; Enter commits the active row, while focused footer buttons retain their own commands. Escape dismisses and returns focus to the opener. Selected, hovered and keyboard-active rows have distinct painted cues.

The chooser anchors to the whole identity card through a weak window reference, targets the larger of the card width and 280 DIP, bounded by the display work area. GTK uses Orca's `PopupWindow` with `wxPU_CONTAINS_CONTROLS` and native popup anchoring; Wayland popup-grab deactivation is distinguished from X11 frame deactivation. macOS and Windows use a frameless modeless `DPIDialog` so the search field can receive typing focus, with display-clamped placement above or below the card. Opening focuses search and closing relays the normal dropdown dismissal state. Frame hide or minimize dismisses the chooser; selector movement closes it. Owner teardown hides it, detaches its owner and frame references, removes frame event handlers and schedules destruction. Popup colors, icons and fonts follow the current theme, and the dialog path reapplies sizing on DPI changes. These source-level contracts do not establish pixel matching, platform runtime behavior or screen-reader support for the painted list.

`ParamsPanel` and `Tab` enable compact settings styling only when hosted in the Prepare sidebar. The Process header places its scope on a separate row using the same underline tabs as the settings categories, with comparison and the object settings table in an overflow menu. The preset picker retains save, delete and search actions. Beneath it, a count of distinct edited values and the inherited reset action show differences from the last saved preset. A single outlined visibility dropdown offers Simple, Advanced and Expert; Developer mode disables changes. Object override tabs retain the visibility row without claiming a preset comparison. Tool selection is labelled Toolhead, uses compact segments and retains the existing scrolling behavior for larger nozzle palettes. Standard-flow tools omit the SF suffix in the sidebar, while hybrid and other flow variants retain their distinguishing suffixes; tooltips name the flow variant. Categories use the approved three-DIP accent underline. Option groups use strong sentence-case headings, extra space above each heading, a 32-DIP minimum row rhythm and a 126-DIP value column; wrapped labels and multiple options can increase row height. Labels and headings share a left edge. The value column follows the sidebar’s right edge with a reserved reset gutter; labels and their leaders expand with the available width. Wrapped row heights and control positions are recalculated on resize. Checkboxes align with the start of the value column. Quiet dotted leaders run from the final label line to the first control at the text baseline; no leader is drawn after a control. Single-line text and numeric fields use 28-DIP minimum heights and six-DIP corners, allowing measured text height to enlarge the control. Compact field fonts adopt the body role's size and weight while retaining the existing locale's font face, including CJK choices.

`TextInput` has an opt-in sidebar renderer used by text fields and selectors. It left-aligns values, places a vector dropdown chevron on the right, uses ten-DIP horizontal padding and reserves a trailing gutter for unit suffixes. Selectors can show a second caption line; preset selectors omit inherited item icons in their collapsed presentation. The native text editor remains responsible for typing, focus and edit events, with measured height and the wrapper's font and palette applied directly. `SpinInput` receives compact sizing, fonts and colors but retains its inherited renderer and step controls. Multiline, full-width, code and specialized editors retain their native sizing. Apart from the opt-in printer chooser, popup menus and full settings dialogs retain their inherited presentation.

The native object tree retains its editing, selection, expansion and drag behavior. Its rows use the body font, a 32-DIP minimum height, 16-DIP indentation and rounded filament badges centered using logical bitmap dimensions, including Retina displays. The search entry shares the outlined field treatment. Selection highlighting remains native on macOS and GTK.

Sidebar styles are reapplied after theme and DPI changes, including preset selectors and nozzle groups. Generated colors are resolved for the current theme before being passed through `StateColor::resolved`, which opts them out of the legacy dark-mode mapping. Native text children receive the field background and foreground directly because they paint independently of their surrounding custom control. Disabled colors and focus borders remain state-dependent. Sidebar action glyphs are raster-tinted for the current theme, preserving alpha and bitmap scale; normal, hover, focus, pressed and disabled bitmap states are replaced together so inherited assets do not reappear during interaction or rescaling. Prepare's modified labels, categories and tool segments use the local `AccentInk` role in both themes. The preset undo glyph is tinted after rasterization with the same role, preserving alpha and scale, and its native interaction states follow the current dirty state. Full settings dialogs retain their inherited modified-text colors. Dirty indicators and reset behavior retain their existing semantics, as do material colors.

Daily Tips uses a compact rounded overlay on the raised surface, with a strong neutral tip heading,
wrapped body text and accent links. The standalone window measures its current tip instead of
reserving a fixed illustration-sized area. Loaded illustrations retain their aspect ratio; missing
illustrations reserve no space. Long tips scroll within the available canvas height. A separated
footer keeps the count at the left and larger outlined previous/next controls at the right; close
and Escape remain available. The embedded slicing tips retain their assigned panel size and
collapse behavior.

The Prepare object toolbar uses one compact floating surface across the main actions, separator, gizmos and assembly-view toggle. `GLCanvas3D`, `GLToolbar` and `GLGizmosManager` share a 12-logical-pixel top inset and compact spacing. A light/dark nine-slice texture supplies rounded corners and the handoff's popover elevation, with a transparent gutter for the shadow. The shadow extends beyond the solid surface without enlarging its hit bounds. Drawing, mouse hit testing and tool input-window placement use the same inset. The 28-pixel base control size retains the user's toolbar size preference, DPI scaling and inherited auto-fit behavior. Design and Assemble canvases retain their inherited toolbar layout.

`GUI/ToolbarStyle` supplies theme and interaction colors for the Prepare glyph atlas: muted ink at rest, a hover surface, accent ink on a soft accent selection, and disabled ink. Atlas generation centers 20-unit glyphs inside 28-unit controls with a pixel gutter, scaling both with the toolbar. Basic actions use the supplied Lucide 0.460.0 paths on a 24-unit grid with a 1.75-unit stroke; the Lucide copyright and permission notice is retained. Specialized slicer tools, including support and seam painting, retain Orca glyphs and provenance. Commands, shortcuts, visibility and enablement rules remain those of the existing toolbar.

For local development, `PORCA_TOOLBAR_STYLE_FILE` can name a UTF-8 JSON file before the application starts. `resources/design-system/toolbar-dev.json` supplies an editable example. Only Prepare's object-tools strip consumes this override: control and glyph size, gap, border, top inset, surface and control radii, and separate light/dark interaction colors. Other controls and font atlases retain their compiled styling. A normal launch reads no override and starts no polling timer. An enabled canvas checks the file every 500ms while visible; active drags defer updates. Each valid edit replaces the complete snapshot against compiled defaults. Unknown fields, unsupported values, oversized files and invalid JSON preserve the last good style and produce a log diagnostic. Removing fields restores their defaults; a missing file preserves the current style.

Reloads update shared drawing and hit-test metrics, invalidate glyph atlases and request an overlay refresh. The live style revision participates in Prepare's overlay signature, so an appearance edit invalidates an otherwise unchanged frame. Texture uploads happen during rendering under the canvas's current OpenGL context. The development surface is generated from the selected colors and radius with the same shadow dimensions as the bundled texture. The original texture remains available if a replacement upload fails. This path changes appearance only; it does not edit printer, project or print settings.


Bundled web pages consume the generated `web/include/porca-theme.css` roles. The native host's `data-orca-theme` attribute takes precedence; setup and older pages stamp `data-porca-theme` from the app-selected user agent. Flush editors use their native JSON theme signal. Shared dialog chrome uses the same charcoal surfaces, coral selection and readable foregrounds as the native UI. The `--orca-*` injected properties remain available to plugins as a compatibility contract. Native ImGui style helpers use generated roles, and shipped UI icon textures recolor inherited teal fills without recoloring external SVGs or bed artwork.

The exact brand lettering remains in the vector logo assets; raster logo crops from the handoff do not replace it. The splash, About icon, troubleshooting logo, window/dock icons and operating-system display names use Porca assets. The underlying executable, settings key, profile and project formats, URL handlers and package identifiers retain their inherited names; branding does not migrate stored printer connections or settings. Orca service identities, licenses and copyright notices are retained.

On macOS the bundle identifier remains `com.orcaslicer.OrcaSlicer` and the registered URL scheme remains `orcaslicer`; the bundle and display names are Porca. `SLIC3R_APP_KEY` remains `OrcaSlicer`, and it names the default application data directory on every platform. Launch Services therefore treats Porca and an installed OrcaSlicer as the same application, so either may open `orcaslicer://` links and associated documents. Unless a portable `data_dir` folder or `--datadir` is used, both read and write the same configuration, presets and saved printers. Separating them requires changing these identities together with a migration of existing user data and link registrations.

The Prepare workspace groups independent plates in named stages using quiet flat regions and thin outlines beneath the physical beds. Stage fills blend the raised-surface role with the workspace plane; outlines use the control-line role. Titles use screen-sized text on the theme's surface, with hover and pressed cues, while following the frame's world position. They expose direct group dragging and a labelled More action. Long names are ellipsized; hover shows the full name unless a locked member requires an unlock message. Titles projected near the toolbars or outside the usable viewport are omitted. The native sidebar menu provides a keyboard route to membership and management for every stage, including empty frames. Saved printer names and their model pictures lead the printer chooser; model presets remain a secondary choice for preparation without a saved device.

Source inspection and successful builds cannot establish native font metrics, fallback rendering, sidebar, toolbar and stage appearance, keyboard interaction or DPI behavior across macOS, Windows and Linux. Those require runtime validation on each platform; observations on one platform apply only to the configurations and interactions exercised there. Local verification records belong in ignored `artifacts/`. Offline appearance checks do not establish working live discovery, a resolved driver crash or physical printer qualification.
