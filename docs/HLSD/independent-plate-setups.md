# Independent plate setups

This experimental workflow is enabled by **Preferences → Control → Configure each plate independently**. A project carrying saved independent setups enables the workflow when opened, regardless of the preference for new projects. Existing projects without the extension retain Orca's shared setup unless independence is enabled explicitly. **View → Next plate / Previous plate** provides menu and keyboard access to switching in independent projects.

Each `PartPlate` owns a `PlatePrintSetup`: the complete resolved print, printer, filament and project configuration, plus the selected destination identifier. Its existing plate overrides, model membership, `Print`, G-code result and validity remain plate-owned. Shared preset definitions are still managed by `PresetBundle`; the bundle is the editing context of the selected plate. Switching captures the outgoing setup and loads the incoming setup through the existing preset loader before applying it to the incoming plate's `Print`. Unsaved setting edits therefore travel with their plate.

The active slice worker must be idle before the editing context can switch. Loading a setup suppresses background scheduling, preset invalidation and capture callbacks until the incoming context is complete. Import restores the final selected plate after object-list selection is rebuilt. Unsaved project state survives loading another plate's presets. Batch slicing continues through Orca's existing sequential worker, activating each plate's setup before slicing it. Since the scene keeps each instance's validity against its own bed, the worker temporarily excludes non-owned instances while copying its slice input, restoring those scene flags even if applying fails. Printer operations remain in Orca's existing device system; independent preparation does not establish concurrent mixed-vendor connections or qualify hardware delivery.

The plate grid reserves cells large enough for the largest bed encountered in the project. Enlarging a grid cell translates the objects with their owning plate's origin, preserving their physical coordinates. Each plate retains its own outline, exclusion areas, tool areas and height. Changing a printer does not scale or recenter objects. Bounds and colors for inactive plates come from their own setups. Scene refresh and switching do not trim other plates' painted assignments to the selected printer's filament count.

Removing or merging a filament first separates copies of an object that span the active plate and other beds. The active copies receive their own object configuration and painted assignments before the palette shrinks. The separation preserves every instance transform, including deliberate sinking below the bed, and belongs to the filament edit's undo snapshot. Membership and selection are rebuilt without invalidating unrelated plates; plates whose object ownership changes become stale.

Independent projects have a shared workspace plane beneath their beds, with a quiet grid and colors following the application appearance. The plane is display geometry; it never participates in picking, plate membership or slicing. Its cached geometry expands around the plate layout.

Each plate has an always-available six-dot grip to the left of its name. Dragging the grip or title text moves the plate; clicking its bed selects the setup without changing the camera. The adjacent pencil remains a separate rename action. The lock control prevents workspace movement as well as automatic arrangement. There is no separate movement mode. Explicit camera-fit commands remain available. Motion translates the bed and all its instances together using full floating-point precision. Beds keep a five-millimetre separation, and moves are unavailable during slicing. The first move fixes the existing plates' absolute workspace positions, preventing later additions or removals from reflowing them; a new plate is placed to the right of the layout. A gesture forms one undo step. Workspace positions are included in undo snapshots and optional `orca_plate_workspace_position` 3MF metadata. Missing metadata retains the automatic grid. Only the moved plate's slice becomes stale, since Orca's cached print geometry uses workspace coordinates; the generated physical coordinates remain bed-relative after slicing again.

Undo snapshots carry the setup with the plate. Project 3MF archives store versioned `orca_plate_print_setup` metadata alongside each plate in `Metadata/model_settings.config`; workspace positions use `orca_plate_workspace_position`. These are optional additions to Orca's existing project metadata, without a new file extension or a required core 3MF extension. The readable configuration is supplemented by numeric values for enum, floating-point and bed-point options, since Orca's text formatting can round numbers or lack enum names. Live dynamic routing and local connection addresses, credentials and certificate paths are excluded at serialization and import, including configs supplied directly to the serializer. Unknown print options, unsupported versions, incomplete required settings and malformed bed dimensions fail project restoration instead of substituting defaults. Geometry-only import skips these additions and can recover models even when the plate setup is unsupported. Saved workspace positions are applied after all plates have been constructed, before rebuilding model membership.

The version-1 setup also carries an optional printer display name beside its destination identifier. Earlier version-1 files without a display name still open. A printer missing from this computer's saved devices does not prevent editing or erase the intended destination on subsequent capture and save. An actionable notification offers Add printer; selecting another printer replaces the intended destination, and explicitly removing a saved printer clears that association. Access codes and local connection details are resolved exclusively from the computer's saved devices.

Embedded preset files are also written from a copy with connection addresses, credentials and certificate paths removed; saving leaves the in-memory preset's connection settings intact.

This extension is specific to this fork. Other slicers and older Orca builds do not restore these independent setups and may discard the optional data when saving. Their ability to open the geometry is not evidence of project fidelity. Print-file metadata is enriched from the relevant plate rather than the last active printer.

The implementation retains Orca's editing tools and interface. It is an experiment in preparation and project ownership, not a completed MultiSlicer interface replacement. Material identity reconciliation when transferring between different palettes, heterogeneous project-wide arrangement, concurrent printer connections and physical send qualification require separate verification.

Native verification of the handle interaction uses two different beds and saved settings. Selection preserves the visible camera view; the handle moves only its owning plate and instances; attempting the same gesture while locked preserves both saved origins and transforms. The test project ends unlocked.

Inactive plates retain their physical bed meshes, resolved from their own custom model or saved printer model. Display caches are separate from the active printer and are rebuilt only when bed settings change; movement updates the placement without reloading the mesh. Missing or invalid models fall back to that plate's printable polygon. Printable areas and slicing inputs are unchanged by physical bed rendering.

The selected bed keeps the darker, opaque surface. Inactive physical meshes and printable-polygon fallbacks use the same light-gray surface at 45% opacity, with fainter grid lines. Their physical outlines remain visible while the inactive beds recede into the shared workspace. Switching plates swaps the surface tones. With Satin plastic appearance enabled in Prepare, shadow receivers follow each bed's displayed polygon or physical model, and the shared plane receives shadows at its own height. The optional [studio rendering](prepare-studio-rendering.md) changes only the view.

Printer discovery and saved devices
----------------------------------

The Prepare sidebar's Add printer action and the Devices page share a scan-and-add dialog. Discovery selects at most four up, running, multicast-capable IPv4 LAN addresses, excluding loopback, point-to-point, VPN, bridge, virtual and Apple peer-to-peer interfaces and link-local addresses. It fails closed when no eligible interface exists. On macOS, Snapmaker, Creality, Moonraker and OctoPrint use mDNSResponder through DNS-SD requests scoped to the selected interface indices; Creality's long service types are queried through PTR/SRV records. Bambu SSDP and Flashforge use owned sockets and a shared budget of ten raw probes per second. Flashforge broadcasts come from actual netmasks, and macOS sockets explicitly bind their egress interface to avoid VPN policy routing. A process-wide scan lease is held until cancelled workers have finished and sockets or DNS-SD references are released. The portable raw mDNS fallback also owns its sockets and has an absolute deadline. Results arrive without blocking the GUI and remain available through retries. Direct-address entry handles machines that do not announce themselves. Discovery never guesses a nozzle: the exact printer/nozzle profile is shown before adding, and an unknown model requires an explicit profile choice.

Saved devices are identified by vendor and serial, with address and port as the fallback when no serial is available. Each device has one plate in the current project. Adding an existing device selects its plate; adding another preserves existing bed positions and creates a bed beside them. The first device can reuse an empty, unassigned initial plate. Profile changes are applied after capturing the outgoing plate setup, without invoking the library's save/discard dialog. The add dialog stays open and regains focus after the main frame's queued updates.

The application configuration retains saved device identities and local access codes separately from project settings. Explicit serial-based scan destinations retain their device identifier. Address-based destinations and bare native device identifiers use a random UUID; the local `scanned_printer_destinations` section maps discovery keys and native identifiers to those portable identities. Bare native identifiers are kept local because they can be DNS hostnames as well as numeric addresses. Address edits retain the UUID and old alias. GUI import migrates legacy local destinations, including printers missing locally, while retaining their display names; the serializer rejects unmigrated address-bearing destinations. The aliases and addresses stay on this computer. Selecting or reopening a plate restores connection settings from its locally saved device or native alias. Another computer without that mapping retains the plate's geometry, settings and intended destination but needs an explicit printer association before connecting.

Connection checks run independently of the selected printer and of the legacy Device tab's current agent. Each saved device gets a bounded read-only authentication/status check: Bambu MQTT over TLS, or the existing vendor's local HTTP endpoint. At most two checks may run concurrently, with one new check per second. Checks pause during discovery and reuse a selected printer's live native connection when available. Successful checks repeat every thirty seconds; failures back off from five to 320 seconds, while rejected credentials retry after five minutes. Shutdown cancels and joins pending checks. Transient failures settle before becoming offline, and rejected credentials remain actionable. This follows MultiSlicer's periodic connection-check approach rather than claiming persistent simultaneous control sockets. No upload, motion, heater, or start command is sent by these checks. The Devices page keeps a saved-printer list beside the selected printer's control panel. The scanner is reached through Add printer; Edit printer changes the local name, address and access code, and Remove printer forgets the saved connection while retaining its plate and models. Selection survives list updates by device identity. Open plate is explicit and disabled when the current project does not contain that printer's plate.

Control inspection uses a separate copy of the saved device's printer configuration. The existing live agent, DeviceManager and MonitorPanel use that copy while Devices is visible; printer selection and telemetry skip Prepare's filament/preset synchronization. Hiding Devices disconnects the inspected machine and restores the active plate's connection. Inspection never loads a printer preset, changes the Prepare destination, changes plate geometry or captures a different device into a plate. Orca still maintains one selected native control connection at a time, alongside independent checks for all saved devices.

Bambu and registered native printer agents reuse MonitorPanel. A native view selector replaces its redundant printer picker and navigation sidebar; the camera and printing progress lead the detail view, with the existing temperature inputs and a compact live filament overview beside them. The native movement, fan, speed, light and full AMS controls expand below monitoring through Show controls; collapsing their parent keeps background telemetry from revealing hidden controls. Printer parts, options and calibration remain in the native control header. The legacy standalone monitor retains its original layout. The saved list uses a native single-selection list box for keyboard and accessibility support. Missing Bambu connection support shows an explicit setup action within the selected printer's detail area without blocking the saved list or scanner. Other supported browser-based printers use their local web control page; unsupported controls are stated explicitly. Control actions remain in the existing native/vendor panel; discovery and the connection checker send no physical commands.
