# Prepare studio rendering

Graphics preferences group these controls under **Experimental graphics settings**. **Enhanced material surface** enables a finish based on each part's assigned filament. Legacy enhanced choices enable filament matching, while Classic and unrecognized choices keep it disabled. The serialized `opengl_prepare_surface` key is retained, with boolean values normalized during application configuration loading. New local preferences enable enhanced surfaces, while realistic appearance remains opt-in. The finishes apply to the normal Prepare canvas when realistic appearance is enabled; Preview, Assemble, Design, thumbnails and CLI exports keep their existing rendering. The toggle lives in local application configuration and changes no printer settings, model geometry, project metadata or undo history.

The finishes use an optional variant of the GLSL 140 Phong program. It retains Orca's vertex transforms, clipping and outlines, replacing the printable opaque surface response with a GGX dielectric model. The base color is converted from sRGB to linear light, with a four-percent normal-incidence specular reflectance. Satin retains perceptual roughness 0.46; matte and filled materials broaden reflections, while silk uses an anisotropic highlight aligned with the print plane. Galaxy has scattered reflective flakes with sharper highlights, carbon fiber has fine matte variation, and wood has subtle grain without replacing the filament's selected color. Patterns use mesh coordinates and are filtered with screen derivatives, so they follow a part during workspace movement and fade below resolvable detail. A bounded shader-local tone map returns display colors, using manual sRGB encoding only when the framebuffer is not doing it. Explicit diagnostic colors and helper materials retain their editing role. Painting and other specialized views continue using their existing shaders.

The renderer reads the assigned slot's `filament_type` and `filament_settings_id`, matching recognizable finish words without interpreting the printer suffix after `@`. Unknown or absent metadata uses satin. The active plate reads the live editing configuration; inactive plates read their captured setups. Membership, including partially out-of-bounds parts, determines the owner. Painted mesh regions receive the finish of their own slot, and unpainted regions inherit the volume assignment. These are appearance estimates rather than measured material properties. Filament identity changes are included in scene capture keys even when geometry and colors stay the same.

The world key follows the existing static-light direction. Fill and room reflection use the same rig; Orbit rotates the room consistently with the key. Off disables shadows without switching the material's static light to a camera light. Key visibility affects direct key illumination, leaving fill and reflected room light available in shadow. The legacy whole-image ambient occlusion pass is omitted with enhanced surfaces because it would darken highlights and editor marks; Classic keeps its original occlusion behavior.

`scripts/generate_studio_environment.py` creates an original synthetic room, eight GGX-prefiltered roughness levels and a split-sum BRDF lookup using local NumPy and Pillow. No photographs or MultiSlicer assets are embedded. The resources are ordinary PNGs: a 258 by 1040 RGBM atlas with padded 256 by 128 tiles and a 128 by 128 lookup. RGBM is sampled as data and decoded to linear radiance. The atlas uses no automatic mipmaps. A failed or unsupported resource allocation leaves a hemisphere fill; rejected enhanced shader variants fall back to Classic without blocking editing. The MultiSlicer plastic finish and room setup are appearance references; its Three.js runtime is not a dependency.

Each canvas owns its environment and shadow resources. Radiance uses texture unit 2, the lookup 3, depth shadows 4 and outline depth 5. Draws set sampler and lighting uniforms explicitly because programs and the OpenGL context are shared across canvases. New bindings are restored and resources are released with the context current.

Enhanced rendering builds its depth map before drawing beds. A value shadow context travels through the existing bed render calls, so each inactive physical mesh and polygon fallback receives at its own coordinates. Polygon receivers reuse the displayed triangulation, including custom outlines. Physical receivers use the same thin-sheet transform as their displayed mesh in Prepare and Preview for both independent and shared setups; design views retain the original bed model transform. The shared plane sits one millimetre below the sheet’s displayed top at Z minus 0.04 millimetres. Prepare and Preview sheets are unlit palette-colored receivers, with inactive sheets darker than the active one; shadow visibility is applied before translucent compositing. Bed bodies are receivers, not additional casters.

Light-space fitting encloses printable casters and their projection onto the workspace floor, rather than clamping shadows to the selected printer's bed. The centre is snapped to shadow texels with filter padding. A single bounded 2048 depth map and the existing 25-tap filter are retained. Widely separated beds share this resolution, so fine contact detail depends on layout extent. No per-bed atlas or adaptive quality policy is implied.

Static maps are keyed by displayed mesh revision, transforms, light fit and clipping. The depth pass clips with the visible object's section and Z planes. Changing surface color does not require regenerating depth. Scene captures additionally compare render settings and theme, preventing reuse across an appearance change. Camera motion does not change a static light-space fit; scene edits and plate movement do.

Preview also reuses its toolpath depth map while panning or zooming with an Orbit light. Rotation changes the light fit; layer, feature and section changes alter the caster signature. Loading a slice clears the cached key even when its bounds and segment count match the previous result. Visible toolpaths share a template containing 256 segments per GPU instance, preserving the eight corners and indexed triangles of each extrusion. The final partial instance clips unused segments before fetching path data; reverse drawing order still follows the enabled path list.

Pure tests cover appearance policy, finite fits, moved caster/floor coverage and capture invalidation. The opt-in `PORCA_BUILD_VIEWPORT_RENDER_TESTS` target compiles actual shader variants and captures simple Classic/Satin fixtures in a minimal wx/OpenGL executable without `GUI_App`, printer services or plugins. It is excluded from automatic CTest execution. Those fixtures do not establish native painting, drag, save/reopen or cross-platform visual acceptance. The local Mac testing restriction remains applicable.
