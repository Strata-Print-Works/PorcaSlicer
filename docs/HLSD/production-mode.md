# Production mode

Production mode is an optional record in a saved Porca project. The Production tab shows overall progress and groups parts under their current stages and plates. Empty stages are omitted from this view while remaining in the editable workspace. Parts appear as wrapping visual cards, each with a thumbnail of its model instance, its usable count against the needed quantity, and an editable target. The same previews appear when reviewing the result of a print. Preparing and slicing the project remain editable while production is active.

Part previews are generated locally from the model geometry and current orientation through the existing OpenGL thumbnail renderer. They render one at a time after the view appears; before Prepare has initialized OpenGL, a card shows that its preview is unavailable. Porca caches matching geometry and orientation within the open project, so repeated instances on different plates share a preview. These images are display aids, not part of the portable production ledger; if a part is removed after a run, its recorded result remains but its preview is unavailable.

Each printable model instance receives a UUID when production begins. Porca stores that identity on the instance in the 3MF build item. Moving a part between plates or stages retains its identity; a duplicated instance starts without one. Viewing the Production tab never changes the project. Parts without an identity in the record, and copies that share one, are shown as not counted yet. **Count these parts**, **Record a print**, **Mark plate done** and a successful send give them identities and add them to the record; the change to the instances is one undo step. The project metadata contains a versioned production ledger with targets and print runs. Each run records the part IDs and transforms on its plate at submission, a printer label, time and source. Reviews append to the run; a corrected result keeps its earlier review. Ready counts derive from the latest accepted quantities for each run, capped at the target for each part.

Porca records a successful print or upload handoff as **Sent**. It does not treat that handoff as printer completion or a usable part. The user reviews a sent run and chooses which parts were good. **Mark plate done** confirms that every current part on that plate is usable. It completes a matching pending run when one exists, or records a manual run when the print was missed. The action is unavailable once all of that plate's parts meet their targets. **Undo mark done** appears beside the completed plate and its print-history entry. It removes only that manual completion or restores the preceding Sent/Printing state and its unreviewed result. Earlier accepted quantities, other runs, and targets remain intact. A corrected result is handled through **Correct result** instead. Undo matches stable part identities and placements across the workspace rather than a plate number; when the plate's contents or placement changed, print history explains why undo is unavailable. A print started elsewhere can also be entered with **Record a print** as still running or with partial results. Stages group work but do not schedule or reserve printers.

In Prepare, a plate title shows **Done** with a check when all printable parts currently on that plate have met their production targets. The cue updates when results, targets, or plate contents change; plates without an active production record have no completion cue.

The 3MF carries the portable record. Before each ledger update, including an undo, Porca writes a numbered local journal snapshot under its data directory, keyed by project UUID and the saved file's location, so a copy saved under another name keeps a separate journal. Moving or renaming the file outside Porca means unsaved journal entries are not restored. Each snapshot is written to a temporary file and renamed into place. The three newest are kept: the newest restores progress, and the others cover a newest snapshot that cannot be read. On project load, a newer local snapshot restores unsaved production progress and marks the project dirty so the next Save embeds it. The undo is a new revision of the full record, so an older journal cannot reapply the removed completion. The ledger stores printer labels and run results, without configured connection addresses, credentials or local file paths. A project moved to another computer carries the last saved 3MF ledger, not unsaved local journal entries.

Current send events do not provide a trustworthy terminal printer job identity across vendors. Production therefore leaves sent runs awaiting a person's review; it does not infer printing, completion or failure from connection health. The record preserves the sent state across restart, including when the selected printer is unavailable.
